1. Introduction 
The Mini -Project is a 30 -mark applied -learning component of the Prompt Engineering course for B.Tech 5th 
Semester. The project is intended to move students from prompt concepts and experimentation to the design, 
testing, evaluation and demonstration of a useful prompt -engineering solution. Teams are expected to identify a 
meaningful problem or use case, develop prompt strategies and workflows, evaluate outputs systematically, 
document iterations and demonstrate a working solution. 
The prescribed Problem Pool/Bank is retained as a common source of real -world problem statements. For this 
course, students should reinterpret a selected problem through a Prompt Engineering lens: define the user/task 
context, identify where generative AI or language-model interaction can add value, design prompts and workflows, 
establish evaluation criteria, and demonstrate reliable and responsible outputs. 
2. Mini-Project Objectives 
• Translate a real-world problem into a well-defined AI/prompt-engineering task. 
• Design effective prompts using appropriate prompt structures, instructions, context, constraints, examples 
and output specifications. 
• Experiment with prompt variants and document an iterative prompt-development process. 
• Use structured evaluation criteria to assess relevance, correctness, consistency, completeness, safety and 
usefulness of outputs, as appropriate to the project. 
• Design prompt workflows that may include multi -step prompting, role/task decomposition, structured 
outputs, retrieval/context injection or tool-assisted workflows where relevant. 
• Demonstrate responsible use of generative AI, including privacy, b ias, hallucination, safety, copyright and 
human-oversight considerations where relevant. 
• Communicate the technical design, results, limitations and practical value of the project. 
• Ensure meaningful and assessable contribution by every team member. 
3. Team Formation and Working Rules 
• Each Mini-Project team shall consist of 3–5 students. 
• One member may be designated as Team Leader/Coordinator for submission and communication purposes. 
• Each team shall work on one project/problem. 
• Every team member must have a defined role and contribute to research, prompt design, experimentation, 
evaluation, implementation, documentation or communication. 
• The final presentation/viva-voce must include participation from each team member. 
• Teams should maintain evidence of indivi dual contribution, including prompt iterations, experiment logs, 
evaluation sheets, repository/version history, design work, documentation and presentation material.

Students may select their Mini-Project through either of the following routes. 
4.1 Select a Problem from the Prescribed Problem Pool 
The complete Problem Pool attached as Appendix A is provided as a student-help resource. Teams may select one 
problem statement from the pool and develop a Prompt Engineering solutio n around it. The selected problem

5. Prompt Engineering Skills to be Demonstrated 
Depending on the selected project, students should demonstrate relevant skills from the following areas: 
• Task decomposition and problem formulation for language-model-based systems. 
• Clear instruction writing and prompt structuring. 
• Role/context specification and audience-aware prompting. 
• Few-shot and example-based prompting where appropriate. 
• Constraint-based prompting and output-format specification. 
• Structured outputs such as JSON, tables, schemas or other machine-readable formats where appropriate.

• Prompt chaining and multi-step workflows for complex tasks. 
• Prompt comparison, A/B experimentation and iterative refinement. 
• Context management and grounding using provided documents/data where appropriate.

6. Suggested Prompt Engineering Project Workflow 
Stage Expected Work 
1. Problem Definition Define the user, problem, context, inputs, desired 
outputs and success criteria. 
2. Prompt Task Design Translate the problem into one or more prompt -
engineering tasks. 
3. Baseline Prompt Create an initial prompt and record representative 
outputs. 
4. Prompt Iteration Experiment with instructions, context, examples, 
constraints and workflow structure. 
5. Evaluation Test prompt versions against a defined test set or 
evaluation rubric. 
6. Error Analysis Identify failure cases, inconsistent outputs, 
hallucinations, ambiguity or other weaknesses. 
7. Refinement Improve the prompt/workflow based on evidence from 
testing. 
8. Prototype / Integration Demonstrate the prompt as part of a useful 
application, workflow or interface where feasible. 
9. Responsible-Use Review Check privacy, safety, bias, copyright, security and 
human-oversight considerations. 
10. Final Demonstration Present the problem, prompt strategy, evidence, 
results, limitations and working demonstration. 
7. Academic Integrity, Originality and Responsible AI Use 
• Students must acknowledge external sources, datasets, models, tools, APIs, documents and references used. 
• The selected Problem Pool statement may be the starting point, but the team's prompt design, experiments, 
evaluation, prototype and documentation must be its own work. 
• Prompt outputs must not be presented as fa ctual evidence without appropriate verification when factual 
accuracy matters. 
• Students must not fabricate evaluation results, user feedback, testing evidence or implementation claims. 
• Sensitive or personal information should not be entered into AI systems  unless its use is explicitly permitted 
and appropriately protected. 
• Teams should document significant AI -assisted development where required by faculty/course instructions 
and remain responsible for the submitted work.

12. Recommended Final Project Report Structure 
Front Matter: Title page, team details, declaration/certificate if prescribed, acknowledgement, abstract/executive 
summary and contents. 
Chapter 1 — Introduction: Problem context, motivation, objectives, users and project scope. 
Chapter 2 — Problem & Domain Analysis: Problem evidence, stakeholders, requirements, domain context and 
constraints. 
Chapter 3 — Existing Solutions & Literature: Comparable solutions, literature, prompt-engineering approaches 
and gap analysis. 
Chapter 4 — Prompt / Solution Design: Task definition, prompt architecture, instructions, context, examples, 
constraints, output schema and workflow diagrams. 
Chapter 5 — Prompt Development & Implementation: Prompt versions, experiments, model/tool configuration, 
prototype/application implementation and integration. 
Chapter 6 — Evaluation & Testing: Test set, evaluation criteria, rubric/metrics, comparative results, error analysis 
and failure cases. 
Chapter 7 — Results & Discussion: Results, i nterpretation, limitations, reliability and lessons from prompt 
iterations. 
Chapter 8 — Responsible AI / Impact / Business / Research Contribution: Privacy, safety, bias, copyright, 
human oversight, sustainability/social/business/research value as applicable. 
Chapter 9 — Conclusion & Future Scope: Key outcomes and future improvements. 
References: All cited sources, tools, models, datasets and external materials in a consistent format. 
Appendices: Prompt versions, test cases, evaluation sheets, sample inputs/outputs, screenshots, supporting 
evidence and additional material.

14. Prompt Experimentation & Evaluation Evidence 
• Maintain a prompt version history showing meaningful iterations. 
• Record representative test inputs and outputs for important experiments. 
• Define an evaluation rubric or criteria before making broad claims about improvement. 
• Compare baseline and refined prompts where appropriate. 
• Document failure cases and explain what was changed in response. 
• State model/tool limitations and any assumptions that affect the results. 
• Avoid cherry-picking only successful outputs when presenting reliability. 
15. Evidence of Individual Contribution 
Because contribution by each team member is assessed, teams should maintain continuous evidence of 
individual work. For Prompt Engineering projects this may include prompt  design, test-set creation, evaluation, 
domain research, coding, workflow design, UI development, documentation, responsible-AI review, presentation 
and communication. 
• Maintain a contribution log. 
• Use Git/version history where applicable. 
• Retain prompt versions and experiment records. 
• Record meaningful stakeholder or faculty discussions. 
• Ensure every member can explain the project's prompts, workflow, evaluation and limitations during viva.
