Repository or project folder (Q12)
A public GitHub repository, or a Google Drive / OneDrive folder set to "Anyone with the
link can view". Use this structure:
README.md      What the project does, how to open/run it, team members, 
prototype link
prompts/
   v1/, v2/, v3/   Older prompt versions, one .txt or .md file per prompt
   final/          Final prompts, one file per prompt
code/          Code, notebooks or exported flows (if any)
test-data/     Inputs used in the test table, and saved outputs
docs/          Diagrams and the Milestone 2 PDF
CHANGELOG.md   Dated list of changes since Milestone 1
No-code teams still keep prompts/, test-data/ and docs/.
Show progress since Milestone 1: GitHub commits with dates, or dated entries in
CHANGELOG.md.
Never upload API keys or passwords. A visible API key means 0 for the repository
part.

horizontal both work. The demo must be a real run; mock-up screens get 0 for the demo

Only one form per team. If you made a mistake after submitting, inform your faculty
before the deadline. Do not submit a second form.
Common mistakes that lose marks
A link that asks the evaluator to request access
Prompts pasted as screenshots instead of text
Diagrams copied from the internet, or not matching what you built
Only one prompt version, or an iteration log with no observed results
A test table where every test passes and there are no edge cases
Numbers in the form that do not match the PDF
Claiming modules as working that do not work
API keys visible in code or config files
No commits or changelog entries after Milestone 1
A reel shorter than 90 or longer than 150 seconds, or one that shows only slides
PDF sections out of order or missing headings
More than one form submitted by the same team
For any doubt, ask your faculty before 20 November so there is time to fix it.
